# 问题与书的记录规范

仅在需要保存或读取图谱时使用。默认使用普通 Markdown，不要求数据库或特定笔记软件。复用用户现有库的位置和格式；用户已要求本地积累但未指定位置时，在当前工作目录使用 `question-library/` 并告知位置。普通讨论只提供增量草案。

## 最小结构

有新记录才创建相应文件，无需提前生成空目录。

```text
question-library/
  index.md
  questions/Q-001.md
  methods/M-001.md
  books/B-001.md
  evidence/E-001.md
```

ID 是本库中的稳定标识。新建前检查既有 ID 和相近条目，不按当前对话从 001 重新编号。不在重命名时改 ID。索引只列 ID、标题、别名和路径，正文保存具体关系与依据。

### 问题 Q

- 问题表述与别名。
- 具体场景、目标或希望理解的现象、约束和时间尺度。
- 基本问题；若已有相应问题节点，以 ID 连接。
- 关联方法与关系：帮助解释、帮助决策、提供反例、澄清价值冲突等。
- 每条关系的前提、依据、状态，以及尚未解决的部分。
- 问题之间的关系：具体化、子问题、依赖、共享机制假设、重构自。

不要为了统一问题而丢掉关键约束。例如“尽快完成”和“降低失败风险”即使主题相近也不必合并。

### 方法 M

- 一句可调用的解释或操作；注明是解释模型、操作策略还是理解视角。
- 触发线索、作用机制、关键前提与失效条件。
- 作者主张及对应 B-ID 的具体材料定位。
- 作者依据与局限；若多书共用一份依据，注明来源依赖。
- 我们追加的综合与迁移推断，单独列出。
- 可比较的其他方法 ID；哪些情形冲突、互补或可替代。

不同作者提出看似相近的方法时，先比较机制与条件。不能仅凭同名合并。多个来源的表述保留各自归属，综合命名属于我们的推断。

### 来源书 B

- 书名、作者、版本或用户给定的识别信息；未知项明写未知。
- 实际可用材料与覆盖范围，原始链接或本地路径。
- 已读取部分中的主张、依据和实际定位。

书籍记录保存来源，不复制整本书。只有书名时仍可建立候选记录，但不能为它补造章节证据。

### 反馈或证据 E

- 类型：用户观察、原始研究、作者案例、二手转述或推演。
- 关联的问题 ID、方法 ID，及具体被检查的主张或应用关系。
- 来源、日期与情境，观察前的预期、实际结果或摘录要点。
- 支持、反驳或限定了什么；不能得出什么。
- 执行偏差、替代解释和下一次需要检查的内容。

模拟输出属于推演，不能登记为实际应用。没有反馈日期、执行情况等信息时保留未知，不补写完整故事。

## 每条连接的证据状态

把状态放在关系上，不用一个综合分数给书、作者或模型评级。分开两个维度：

1. **归属与推断性质**：原文明确／笔记转述／我们的综合／迁移假设／待核验。
2. **当前应用证据**：未实践／有情境内支持／有反例或冲突／证据不足以区分。

例如，“本书明确提出 M”可以已核对原文，而“M 能帮助 Q”仍是未实践的迁移假设。不能因为出处可信而直接认定应用有效。

关系可用这一紧凑格式，无需为所有记录建立重复的关系文件：

```text
Q-001 —帮助解释→ M-002
条件：目标场景满足哪些前提
归属与推断性质：我们的综合
依据：B-001 的可定位段落；E-003 的场景观察
当前应用证据：有情境内支持
未解决：仍有哪些竞争解释
```

问题文件是“问题—方法”连接的正文归属处；方法文件保存“方法—书”的来源连接；反馈文件保存观察。索引、反向链接和图是导航，不另维护一份相互竞争的关系正文。简单展示可以把箭头反向画成“方法帮助问题”，但语义必须明确。

## 增量与纠错

写入前读取相关现存条目，区分新增、补强、冲突、限定和待核验。检查 ID 未占用、目标文件存在、链接不会悬空。

问题是否相同，比较目标、约束、机制和尺度；措辞相近只作为候选。证据不足时建立关联，不急于合并。用户要求合并且确实同义时保留旧 ID 的重定向记录并更新引用。

发现冲突先并列记录；后来改结论时保留原判断、修改依据与日期。没有理由时不覆盖旧反馈。若合并会丢失用户有意保留的区别，先保留分支再提出合并建议。

写入后重读变更条目，检查引用和状态。交付本次增量摘要及路径。写入不可用或失败时交付可复制的内容和待保存位置，明确没有保存成功。

跨聊天使用必须有可读入的记录。新聊天先读索引，再按问题读取相邻条目；找不到库时说明当前未载入历史，不假装记得此前的案例。
