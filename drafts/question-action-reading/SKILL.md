# 问题驱动阅读与问题书网

让书中的知识能被问题找到、在适当条件下被使用，并接受后续证据修正。保存问题、解释或方法、出处和反馈之间的联系；不以读完、概念数量或图的大小为目标。

## 入口与交互

从用户当前请求选择入口，用户可以中途切换，不要求走完整流程。

| 请求 | 工作方式 |
|---|---|
| 带我学、陪我读、检查我的理解 | 教练：先了解真实问题，先让用户表达理解，一次推进一个关键问题，等回答再继续 |
| 这本书解决哪些问题、整理书的问题地图 | 提炼：基于已有材料直接给出问题与方法，不强求用户先有个人问题 |
| 针对这个问题比较几本书、找跨领域方法 | 比较：读取相关记录或材料，比较机制、条件、分歧与选择依据 |
| 记入问题库、补充一本书、更新应用结果 | 积累：先读已有记录，再提交最小增量；记录规范见下文 |

明确要求直接解释或整理时直接产出。缺失信息会改变结论时，只问当前最关键的一项；其余部分继续完成。用户已经给出的问题、材料和偏好不重复询问。

## 证据与阅读范围

先说明可用材料的覆盖范围：全文、部分章节、用户笔记、二手介绍或只有书名。只有书名或二手概述时，可以给待核验的候选关联，不能声称已经完成对全书的蒸馏。

对关键内容分开记录：

- 作者主张：作者明确说了什么，原文定位在哪里。
- 作者依据：作者使用的研究、论证或案例；案例不自动成为普遍证明。
- 我们的推断：对原文的解释、跨书综合或迁移假设。
- 用户经验：何时、何种条件下发生了什么，支持或反驳哪项判断。

不编造引文、页码、章节或作者立场。有版本时记录版本；无页码可用章节标题、用户材料段落等真实定位。已有材料不支持的归属保持待核验，检索可用且任务需要时再补来源。

## 保留原有教练闭环

真实问题 → 基本问题 → 拆结构 → 调用模型 → 判断边界 → 最小行动 → 反馈修正。

基本问题只比具体场景抽象一级，同时保留原场景。围绕当前卡点补最少必要知识，不为覆盖全书展开所有概念。用户的理解已经足以支持判断、说清边界并形成下一步时停止扩展。

结束时简要给出 Learning State：当前问题、基本问题、结构、关键方法、边界、理解变化、下一步及悬而未决的问题。只有实际发生交互摩擦或用户要求评审时，补充 Skill Feedback，分开记录方法的使用结果和技能规则的改进建议。

问题框架、竞争解释或系统分析成为主要任务时，若环境有 Question Framing 或 Question → Explanation → Action，可按需交接。不存在这些技能时仍完成必要的澄清、竞争解释和证据比较，不把它们当安装前提。

## 从书中提炼问题与方法

1. 确定本次材料范围。沿作者的疑问、反对意见、案例中的困难和推理结论，提取材料实际回答的问题。
2. 将宽泛主题改写成能区分回答的问题。例如“效率”不是问题，“任务同时开展较多时，为什么单项完成反而变慢”才有可比较的结构。
3. 区分作者的问题与我们认为可帮助的问题。后者属于推断，不能改写为作者目的。
4. 提炼最少必要的方法单元：触发场景、解释或操作、机制、前提、边界、出处。术语名或金句本身不构成一个方法。
5. 提供问题到材料的定位：当前问题值得读哪一部分，预期获得什么，哪些部分尚未覆盖。

问题可以是解释、决策、设计、理解或价值判断。方法可仅提供解释、反例或视角；无法推导行动时保留这一性质，不强行写行动方案。

## 从问题比较跨书回答

先检索已有问题、别名、具体案例与相邻方法。以问题的目标、约束、机制和尺度判断匹配，而不是仅凭词语相近。

按本次需要比较：

| 方法及出处 | 解释问题的哪一部分 | 成立前提 | 预期可见信号 | 失效边界 | 与其他回答的关系 |
|---|---|---|---|---|---|

关系应具体说明是补充、替代、冲突，还是不同条件下的回答。相同情境下出现相反主张时保留冲突，指出什么证据能区分；缺证据时不编一个统一结论。多本书引用同一研究或案例，不算多份独立验证。

没有足够材料时说明覆盖缺口，不为凑齐领域或方法数量编书单。找新书时说明它预计填补哪个缺口，并核实书目与相关内容。

### 跨领域迁移

逐一对应原场景与目标场景的关键变量、关系、前提和尺度；明确不相同的部分。共享“成长”“反馈”“效率”等词语不构成机制相同的证据。

能够对应时给出迁移假设、一个可能失败的条件，以及可区分它与竞争解释的观察或小实验。无法对应时只保留启发性类比，不把它作为当前行动的已证实依据。

同一种方法可以连接多个问题，但每条应用关系都有自己的边界与验证状态，不给方法统一授予“跨领域有效”标签。

## 积累与反馈

需要保存、读入既有问题库、跨聊天衔接或输出结构化图谱时，读取 [记录规范](references/network-records.md)。不需要持久化的讨论直接用简洁文字或表格，不强制创建整套卡片。

新增书籍时先匹配已有节点，报告本次新增、补强、冲突、限定或待核验的关系。书中出现过某种方法，与该方法在某个场景中有效，是两件不同的事。

应用前写清预期信号；应用后比较实际观察，并区分方法假设、适用边界、执行差异和问题框架。失败可以产生新问题或收窄旧连接；单次成功也不升级为普遍规律。

知识记录的更新不自动改写 SKILL.md。只有用户要求改进技能时，才将反复出现的交互失败转成规则修改建议；需要比较草案效果时读取 [试用案例](references/acceptance-cases.md)。

## 交付与停止

交付贴合入口：教练给学习状态；提炼给问题地图与材料定位；比较给条件化回答和下一步；积累给记录增量与保存位置。图有助理解时从记录生成简洁图示，不把图的完整性当目标。

当当前问题已有足够依据推进，或新增材料不再改变判断时停止。证据不足时交付已知部分、最关键缺口和下一步，不把材料不足写成整个问题无解。

试用状态：本版本是待真实阅读验证的草案。与正式同名技能比较时按路径明确指定使用哪一份，避免同时加载两个版本。
